# 内容工作台 V2：站内编辑审核与公开发布

日期：2026-10-28。状态：已接入真实生成、编辑和发布后端；生产启用由发布目录的 `deploy/editorial-enabled` 控制。静态原型仍单独保留，不能用于实际发文。

## 已确认的目标

业务人员上传 PDF 后由后台自动生成文章，成功进入站内审核草稿箱。业务人员直接修改正文、标题、摘要、图注和配图裁框，预览并确认后公开发布公众号及多语言 Blog。公众号不自动群发，现有公众号排版、产品模块和阅读原文引导保留。

业务人员可以处理普通裁图错误；管理员处理源文不匹配、生成失败和裁剪器系统性问题。修图不再需要重新生成整篇正文。

## 工作流

```text
上传 PDF → 排队/生成 → 审核草稿箱 → 编辑与预览 → 确认并发布
                         ↑                         ↓
                 保存、裁图、恢复版本         后台发布任务
                                             ├─ 中文 Blog
                                             ├─ 公众号公开文章
                                             └─ 英/日/韩/俄 Blog
                                                   ↓
                                       渠道结果 + 链接 + 飞书通知
```

生成阶段不公开发布。业务人员只有一次发布确认，明确写着“公开发布文章，不群发”。后台可以关闭页面继续运行，页面读取任务状态不能启动发布。

中文 Blog 是现有公众号“阅读原文”的目标，因此必须先取得其有效公开链接，再完成公众号素材组装及公开发布。这是后台依赖，不要求业务人员多点一次。其他语言从已确认修订生成；不复用源稿哈希不同的历史译文。

## 页面与操作

### 工作台

导航只有：审核草稿箱、生成中、发布记录。失败状态出现在对应列表，并给出一个可执行的处理入口。

- 上传时只选 PDF，业务线来自当前登录权限；管理员可以切换业务线。
- 上传成功即反馈“已排队，可关闭页面”，不要求另选一次文件。
- 同一业务线按 PDF 内容哈希识别重复，默认回到已有文章；重新生成必须显式建立新修订，不能覆盖人工编辑。
- 待审文章主操作“编辑审核”；生成失败主操作“重试生成”；部分渠道失败主操作“查看发布结果”。
- 不将翻译、图片抽取、公众号素材写入等内部阶段做成业务人员的多组操作按钮。

### 编辑审核

主区域是富文本正文；标题、摘要单独编辑，正文不重复大标题。支持段落、H2/H3、加粗、斜体、列表、引用、链接、表格、图注及图片块。不能直接输入任意脚本或 HTML 样式。

- 自动保存到服务器，展示“保存中 / 已保存时间 / 保存失败”。未保存成功时不可发布。
- 保留生成原稿及修订历史；恢复产生新版本，不破坏历史。
- 保存采用乐观锁。另一人已保存时提示冲突，保留当前未保存内容，不能静默覆盖。
- 右侧按需显示 PDF 原页、封面和来源信息，保持正文编辑区宽度。
- 图片可从完整 PDF 任意页重新框选，而不只是裁掉当前错误图片的边缘。若自动抽图失败，仍允许进入编辑器，从原页补齐图片。
- 正文图片自由比例裁剪；封面单独处理，不用列表卡片的裁剪方式截断科学图。
- 裁剪保留原 PDF、页码、坐标和操作者，随时恢复。放大不改变源像素，不使用生成式工具补画科学结果。
- 支持拖动裁框，同时提供数值输入用于精确调整和键盘操作。图片过小、框选越界、正文引用失配应在当前图旁显示错误。
- 普通图片修改只重渲染相应页面/图片，不重跑文章生成或所有页抽图。
- 只有缺失图、无法解码、越界、源稿不匹配等可验证问题硬拦截；旧自动裁剪的置信度不应使人工修正后的有效裁框再次无法提交。科学语义由业务人员确认。

### 预览与发布

编辑器提供公众号和 Blog 预览。正式公众号预览必须调用现有 `markdown_to_wechat_html` 及同一组装函数，保留字体、小标题、产品模块、阅读原文引导，禁止另写一套“近似模板”作为验收依据。

点击“进入发布”展示最终版本、公众号账号、目标语言、封面和公开发布说明；点击“确认并发布”完成一次审核并冻结修订。这次点击不是群发授权。

提交成功立即显示“已提交，可关闭页面”。结果页逐项显示公众号和 5 个语言 Blog 的状态、公开链接、错误及适用的单渠道重试入口。全部目标验证成功才显示“全部发布完成”；部分成功必须展示部分成功。

## 数据与后台契约

新增独立的修订和发布任务，不通过给旧 `published` 枚举换文案来实现。

| 实体 | 关键字段和约束 |
| --- | --- |
| `editorial_revisions` | job_pk、revision_id、parent_revision_id、editor_document_path、title、digest、source_pdf_sha256、asset_manifest_id、author、created_at；正文文件不可变 |
| `editorial_heads` | job_pk 唯一、current_revision_id、lock_version；保存要求客户端 expected_revision 匹配 |
| `publication_requests` | request_id、job_pk、revision_id、reviewer、reviewed_at、targets、状态；相同修订和目标幂等 |
| `publication_targets` | request_id + target 唯一、状态、远端 ID/URL、尝试次数、最近错误、回读证据；只重试失败项 |
| `crop_assets` | source_pdf_sha256、page、bbox、render_scale、image_sha256、操作者；不可覆盖原图 |

正文采用结构化富文本 JSON，发布时从同一修订导出 Markdown，继续复用现有模板与翻译。图片块引用资产 ID，不接收用户任意服务器路径或图片 URL；保存时校验图号、图片块和资产映射。

发布任务读取自己的不可变快照。提交后继续编辑会生成下一修订，不能改变正在发布的内容，也不自动覆盖线上文章。更新已发布内容须再次显式确认，并保留旧发布记录。

生成与发布队列须持久化，支持进程重启后的恢复、租约和阶段检查点。网页轮询只读取状态。不要用全局单个后台进程锁让一篇慢 PDF 阻塞全部编辑和状态请求。

### 微信公开发布

官方资料已读取：

- https://developers.weixin.qq.com/doc/service/guide/product/publish.html
- https://developers.weixin.qq.com/doc/service/api/public/api_freepublish_submit

官方说明：需要先保存草稿素材，再用 `media_id` 调用 `freepublish/submit`；返回 `publish_id` 仅表示提交，必须等待发布结果。权限取决于账号主体、认证及实际接口授权，两条业务线都需核实。

后台阶段：组装模板 → 上传图片/封面 → 建立内部草稿 → 回读内容 → 记录提交意图 → 提交公开发布 → 保存 publish_id → 查询/接收结果 → 取得公开 article_id 与 URL → 内容/图片回读。

请求断线且没有 publish_id 时属于“结果待核对”，禁止盲目重新提交。先核对远端；能证明未提交或明确失败才允许重试。不实现消息群发接口。无公开发布权限时在发布前展示阻断原因，不能把进入微信草稿箱显示为公开成功。

### Blog 与通知

- 译文来源必须是最后审核的正文。标题、摘要、SEO 元数据、图注随语言转换，图片资产保持一致。
- 中文 Blog → 公众号存在“阅读原文”依赖；外语 Blog 独立记录结果，单个语言失败不撤销已成功渠道。
- 保留现有线上正文、图片、封面及 URL 校验。HTTP 200 或 CMS 接受不等于业务完成。
- 既有飞书收信配置沿用；完成通知带业务线、公众号公开链接和全部 Blog 链接。部分失败通知明确标注已成功/未成功，不发“全部成功”。通知按请求与收件人幂等。

## 验收与上线

1. 上传一次后自动入队，刷新/重启不会丢任务或重复生成；生成完成进入站内草稿。
2. 实际错误样本：从 PDF 换页重新框选，保存后精确保留正文；7-1 的左右栏与跨图注情况作为裁剪回归样本。
3. 图片提取失败时仍能编辑文字并从原页补图；缺少必需图时不能发布。
4. 保存失败、并发编辑、关闭页面、恢复版本均不丢人工修改。
5. 编辑后的正文、图片、封面进入公众号模板，正文不重复大标题；正式预览与发送产物一致。
6. 重复点击发布仅创建一个请求；任务读取固定修订；发布中的另一次编辑不会污染产物。
7. 公众号提交成功、发布失败、超时不确定、成功后回读失败分别展示，不误报；没有任何群发调用。
8. 中/英/日/韩/俄的译文版本与图片对应；只重试失败语言，保留成功回执。
9. GM-LAB 实名、业务线隔离、CSRF、防 HTML 注入、资产白名单与裁剪资源上限通过测试；直达 cookie 不能编辑或发布。
10. 用影子数据端到端验收，分别核实两公众号权限；生产真实公开验收由有权限业务人员确认。迁移只导入待审稿，不自动批准历史稿，不恢复 4-3/4-4。

实施顺序：持久化修订/队列 → 编辑器/裁图 → 同源模板预览 → 按渠道公开发布与回读 → 工作台替换与迁移。每阶段保留现有入口回滚；生产切换前统一验证，不让业务人员使用一半旧、一半新的审批流程。

## 本次交互原型的边界

`prototypes/editorial-workbench/index.html` 可演示草稿列表、编辑文字、从真实 PDF 原页裁剪、公众号/Blog 排版示意和模拟发布状态。所有演示内容只保存在当前浏览器；不会上传 PDF、调用生成模型、修改生产或公开发布。示例文字不是可发布医学文章。正式编辑器需使用维护中的结构化编辑组件，不能把原型的浏览器编辑命令直接用于生产。

## 实现与运行

- 独立入口 `/workbench/aav` 与 `/workbench/solidex`，旧 `/aav`、`/solidex` 与审核链接保留所属业务线。管理员 `/workbench` 先选择业务线，单线人员直接进入自己的工作台。草稿、生成、发布记录和上传均限定当前业务线，采用页面级请求参数而非可被其他标签页覆盖的会话选择。沿用 GM-LAB 实名登录和业务线权限；旧写入 API 在启用后返回 409，业务线快捷 cookie 不能保存或批准。
- 前端为本地打包的 Tiptap 3.32.0，结构化 JSON 保留上下标。运行 `cd frontend && npm ci --ignore-scripts && npm run build` 更新提交到仓库的 `static/editorial-editor.js`；生产不需要 Node 或 CDN。
- 修订、裁框、冻结请求、渠道回执存在共享 `runtime/editorial/`；独立 SQLite WAL 加不可变哈希文件。备份应包含整个目录及原有共享输入、输出、主数据库。不能只备份一份 SQLite 主文件而遗漏 WAL 和资产。
- 生成与发布各一个持锁进程，处理慢任务不占 Web 请求。Web 服务后台每 30 秒检查队列进程；意外退出后从回执恢复。读取页面和任务状态不触发外部发布。
- 发布确认框可选立即发布或定时发布。定时输入和展示统一使用北京时间（UTC+8），后台保存带时区的 UTC 时间；至少提前 1 分钟。实名确认冻结当前修订，任务持久保存为 `scheduled`，到点才领取执行，页面关闭不影响执行。时间表示启动发布流程，并不承诺各渠道同时公开；队列繁忙或服务中断时顺延执行，服务恢复后补执行到期任务。
- 发布记录显示预约时间；执行前可以取消定时，取消后返回草稿箱，可重新编辑或预约。取消和执行领取在同一 SQLite 写事务中竞争，取消成功后旧列表快照不能再执行；已经领取的任务拒绝取消。重复预约幂等；修改时间须先取消再确认。取消与再次预约保留审核人、预约时间及取消审计。待执行的定时任务阻止同文另一发布版本和草稿移除；后续编辑不改变已预约的不可变修订。
- 自动抽图失败不会阻止已生成正文进入编辑器；同事可直接从原 PDF 补图。新上传按 PDF 内容哈希去重；已有正文不重新生成。
- 同修订重复提交返回原请求。CMS 写入/微信提交结果不明会转入 `uncertain`，须管理员核对后处理；前台不提供盲目重发。新请求也不能绕开未核对的旧请求。更新版本发布后禁止旧请求重试覆盖。
- “移出草稿箱”只记录可恢复的可见性状态，正文、PDF、修订和发布回执均保留；可在本业务线的“已移除草稿”恢复。操作保留实名、时间及当时元数据快照，检查当前修订并拦截正在处理的任务。已移除草稿不能继续编辑、入队或发布，须先恢复。
- 微信后台仍按平台要求使用内部草稿素材，业务人员无需进入公众号草稿箱操作。只有公开发布状态成功、取得公开 URL 并回读内容一致才显示完成。每条业务线启动时只读检查 `freepublish/batchget`，正式提交仍可能受微信内容和账户权限限制。
- 每个渠道独立回执；可重试明确失败的渠道。飞书通知沿用现有本人及张晓妍收信配置，带业务线、各渠道结果与链接。4-3 / 4-4 保持暂缓。

## 发布与验收边界

`deploy/verify_editorial_release.py --source <release> --work-root <isolated-temp>` 在隔离目录运行新旧测试，禁止网络、生产数据库与真实工作进程。服务器没有 Node 时明确报告跳过旧 UI 逻辑测试；这些测试及正式富文本页面需在本地浏览器完成。

`deploy/deploy_editorial_release.sh <new-commit> <expected-current-commit> <task-root>` 检查当前版本、解包已推送提交、复用 Python 环境和共享数据、运行隔离测试、确认无旧写入进程、短暂停服切换并检查健康、静态文件哈希、实名边界及历史发布标识未变化。自动验收失败恢复原 release，保留新目录和共享修订数据以便排查。

上线后的手工回滚须先停服务并核对新发布请求是否有未完成或远端结果不明的阶段，保留完整共享状态，不能在旧流程里重新提交这些请求。正式发文验收必须由业务人员审核后点击确认；本地合成数据、接口权限检查和自动化测试不等于生产文章已公开发布。
